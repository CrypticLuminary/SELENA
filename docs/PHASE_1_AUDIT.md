# Phase 1 — Frontend Production Audit

**Audit date:** 2026-09-28  
**Scope:** current Next.js frontend, synthetic-data boundary, privacy UX, dependency posture, accessibility, safety behavior, and CI/security readiness.  
**Result:** Phase 1 implementation complete on the audit branch; draft PR remains the human review boundary.

## Executive result

The V1 frontend has a strong privacy-oriented structure for a prototype: synthetic story/pattern datasets are isolated behind `src/lib/mock-api.ts`, statistics consent defaults to opt-in, story text is not placed in persistent browser storage, public pattern values are banded/suppressed by design, and there is no `dangerouslySetInnerHTML`.

The original audit discovered an important production blocker: `next@14.2.15` had known high/critical security findings. That blocker was remediated rather than waived. The branch now uses `next@16.3.6`, `react@19.3.0`, and `react-dom@19.3.0`; the lockfile was regenerated by a one-time GitHub Action only after lint, typecheck, privacy guard, production build, and production dependency audit all passed. The temporary write-enabled migration workflow was then removed.

## Security findings and remediation

### S1 — Resolved — vulnerable framework baseline
**Before:** Next.js 14.2.15.

CI independently confirmed critical/high production dependency findings and recommended a breaking upgrade rather than a patch within the old line.

**After:** Next.js 16.3.6 + React/React DOM 19.3.0, with Next.js 16 route API and ESLint migrations applied.

**Validation:** current production dependency audit passes.

Security releases remain an ongoing operational requirement. Dependabot and the mandatory dependency-audit job are present so the baseline is not treated as permanently safe.

### S2 — Resolved — baseline HTTP security headers were absent
Added:
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: no-referrer`
- `X-DNS-Prefetch-Control: off`
- restrictive `Permissions-Policy`
- disabled `X-Powered-By`

A deployment-specific CSP is intentionally deferred until final API/asset/hosting domains are known. A guessed CSP would either break valid behavior or encourage unsafe broad exceptions.

### S3 — Tracked — demo removal code uses sessionStorage
The synthetic V1 wizard stores only the demo deletion code and publication choice, not story text, and the success page removes the value after reading it.

This remains acceptable only for the explicitly synthetic demo. A production recovery/removal credential must be handled by the real backend flow, must not be routinely logged, and should not be retained in browser storage.

### S4 — Positive — no dangerous HTML injection found
No `dangerouslySetInnerHTML` use found. CI now guards this invariant.

### S5 — Positive — no real production network layer exists yet
No production API fetch layer exists; V1 remains synthetic.

### S6 — Repository configuration follow-up — GitHub Dependency Graph
The official GitHub Dependency Review action was tested and correctly failed because this repository's GitHub Dependency Graph is disabled.

The workflow was removed instead of being marked allowed-to-fail. The current branch still has:
- mandatory high/critical production `npm audit`
- CodeQL
- Dependabot

Recommended follow-up: enable Dependency Graph in GitHub repository security settings, then restore official Dependency Review as a PR gate.

## Privacy findings

### P1 — Positive — story drafts stay in memory
No story-text localStorage persistence exists.

### P2 — Positive — analytics consent is opt-in
`consentStatistics` defaults to `false`.

### P3 — Positive — public pattern policy is centralized
`src/lib/privacy.ts` centralizes:
- general threshold 10
- sensitive/minor threshold 20
- max two dimensions
- no exact public counts
- no geography
- count bands

These are mock/display policy in V1. Production enforcement must live server-side.

### P4 — Guarded — mock data boundary
`stories.ts` and `patterns.ts` remain accessible to UI code only through `mock-api.ts`.

A CI privacy-boundary script now fails if:
- sensitive mock datasets bypass the boundary,
- `dangerouslySetInnerHTML` is introduced,
- `localStorage` is introduced in frontend source,
- statistics consent ceases to be opt-in by default,
- key public privacy invariants are weakened.

## Accessibility and safety findings

### A1 — Resolved — modal focus could escape
The bottom sheet already moved/restored focus but did not trap Tab within an `aria-modal` dialog.

**Fix:** Tab/Shift+Tab now remain inside the open dialog.

### A2 — Resolved — story sort advertised incomplete tab semantics
The sort buttons used `role="tablist"` / `role="tab"` without implementing the complete keyboard behavior expected of tabs.

**Fix:** use a normal button group with `aria-pressed`, matching the actual interaction.

### A3 — Resolved — Quick Exit navigation could undermine history replacement
The old helper called `location.replace()` and then immediately assigned `location.href`.

**Fix:** use `replace()` as the primary path and `assign()` only as a failure fallback.

### A4 — Resolved — duplicate global Quick Exit hotkey listeners
Multiple visible Quick Exit components are mounted (responsive header variants and footer), so each instance previously registered the same global Shift+Esc handler.

**Fix:** visible buttons are listener-free and one `QuickExitHotkey` is mounted at the app root.

### A5 — Positive — reduced motion and alternative representations
Shared motion code respects reduced-motion preferences, and chart experiences provide list/table alternatives.

### A6 — Later automated test expansion
Browser-level automated accessibility checks are still valuable, but belong with the broader Playwright/E2E test foundation rather than being improvised into this audit.

## Code-quality findings

### Q2 — Positive — no outstanding TODO/FIXME markers

### Q3 — React 19 lint migration improved state flows
The new React lint rules exposed several synchronous loading-state updates inside effects. Where possible, loading state was moved to the user action/retry boundary rather than disabling the rule globally.

One narrow exception remains for the one-time synthetic-demo `sessionStorage` read; it is documented locally because that effect intentionally synchronizes with an external browser API.

### Q4 — Behavioral-test expansion remains later work
There is no full unit/integration/E2E suite yet. Phase 1 establishes a repeatable static/build/privacy/security baseline; broader behavioral automation is tracked for later testing milestones before production launch.
